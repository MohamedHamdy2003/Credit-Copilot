Stage 1 · Extract & Governance

Multi-Format Parsing, Trust Firewall & Metadata Resolution

Before any text is chunked or embedded, Credit Copilot validates file integrity, enforces strict policy-only isolation, and extracts edition & effective dates directly from the document.

ParserRegistry + policy-metadata.ts

Normalized Parsers

PDF
pdf.js Coordinate Sort Verifies %PDF- header, ≤100 pages, preserves page numbers (no OCR).
MD
remark AST Parser Strict UTF-8 decode, tracks Markdown heading hierarchy per section.
CSV
Structured Row Blocks Unique headers, row numbers preserved, feeds exact rows to knowledge.pricing.
All text normalized with NFKC + deterministic SHA-256 file hash.

Zero-Trust Policy Gate

Guarantees customer personal data can never leak into the shared bank policy Vector DB.

✕ Always Blocked · HTTP 403 APP-* / AUTO-* filenames, excluded evidence SHA-256 hashes, or docs containing Application reference + Salary / Bureau / ID.
✓ Allowed · Policy Corpus Only Lending policies, circulars, product sheets, procedures manuals, and pricing tables with verified metadata.
RBAC-gated: only head-credit (can_ingest = true) may upload or delete policies.

Stage 2 · Semantic Segmentation

Clause-Aware Chunking & Deterministic Idempotency

Generic fixed-size chunking splits banking rules in half. Credit Copilot chunks along legal clause boundaries so every retrieved vector preserves full rule context and exact page provenance.

clause-cl100k-v3

Why Clause Boundaries Matter

✕ Naive fixed-size split (500 chars): Cuts right between "CP-4.1 Max DBR" and "40% of verified net monthly income" → broken retrieval & hallucinated limits.
Chunk #4 · Section CP-3.3 p. 3 · 112 tokens

Minimum verified net monthly income requirement (EGP 12,000 under CP-2025) kept completely intact.

Chunk #7 · Section CP-4.1 p. 4–5 · 164 tokens

Maximum Debt Burden Ratio (DBR ≤ 40%) including exact obligations formula and effective edition metadata.

Chunk #14 · Section CP-13 (Comparison Table) p. 11 · Table-Protected

References lower numbers (CP-4.1, CP-3.3) without falsely breaking the parent table chunk.

Token Window & Re-Ingestion Safety

1
Regex Clause & CSV Row Boundaries Detects CP-*, PM-*, PS-*, C-* headings and one chunk per CSV pricing row.
2
Bounded Token Sliding Window (cl100k_base) Only clauses exceeding 800 tokens split further, keeping a 60-token overlap for continuity.
3
Full Provenance Attached to Every Chunk edition · product · effectiveFrom · effectiveTo · pageStart/End · row.
Deterministic Idempotency Key
chunk.id = SHA-256(docId : docHash : "clause-cl100k-v3" : ordinal : contentHash)

Re-uploading an identical policy matches existing active chunks + vectors → stages 3 & 4 are SKIPPED with 0 embedding cost. Different content under the same ID triggers HTTP 409 Conflict.
